# Hardware QR (Автоматизований збір апаратних даних)

## 🎯 Суть проєкту
Метою проєкту є максимальна автоматизація процесу збору інформації про апаратне забезпечення комп'ютерів (наприклад, у сервісних центрах або при інвентаризації).
Замість того, щоб вручну завантажувати ОС клієнта, встановлювати програми для діагностики або розбирати ПК, інженер просто вставляє флешку, вмикає ПК, і на екрані миттєво з'являється QR-код з усіма характеристиками.

## 🛠 Як це працює
Рішення являє собою надзвичайно легкий і швидкий "живий" (Live) образ операційної системи Linux, який базується на мінімалістичному дистрибутиві **Alpine Linux**. Цей образ (`alpine-hardware-qr.iso`) створений таким чином, щоб завантажуватись повністю в оперативну пам'ять (RAM) за лічені секунди.

**Процес використання (крок за кроком):**
1. Спеціаліст записує образ на мультизавантажувальну флешку (наприклад, за допомогою Ventoy).
2. Підключає флешку до діагностованого ПК і завантажується з неї.
3. Система завантажується автоматично, без жодних логінів чи введення паролів, завдяки налаштованому автологіну.
4. Одразу після завантаження запускається головний скрипт збору даних.
5. Скрипт запитує у інженера **номер тікета (заявки)**, якщо такий є.
6. Далі скрипт автоматично витягує всі ключові специфікації ПК:
   - Процесор (CPU)
   - Об'єм оперативної пам'яті (RAM)
   - Модель та серійний номер материнської плати
   - Версію BIOS
   - Відеокарту (GPU)
   - Усі підключені накопичувачі (жорсткі диски/SSD) та їхні серійні номери
7. Зібрані дані виводяться на екран у вигляді читабельного списку для швидкої перевірки.
8. Після натискання клавіші Enter, екран очищується, і генерується великий **QR-код**, який містить усі ці дані.
9. Інженер сканує QR-код телефоном або сканером — і всі характеристики миттєво потрапляють до системи обліку.
10. На екрані QR доступні гарячі клавіші: `Tab` перемикає інверсію кольорів, `E`/`N` дозволяє змінити номер заявки й згенерувати QR повторно, `Enter` перезавантажує ПК, `P`/`S` вимикає ПК.

## 📦 Склад проєкту та архітектура
Проєкт не залежить від зовнішніх сервісів чи Інтернету (все працює офлайн) і містить наступні компоненти:

1. **`src/hardware_qr.sh`**: Серце проєкту. Shell-скрипт, який виконує збір інформації за допомогою системних утиліт (`lscpu`, `free`, `dmi`, `lspci`, `lsblk`) і генерує QR-код через утиліту `qrencode`.
2. **`alpine-config/`**: Папка з конфігураційними файлами для збірки Alpine Linux:
   - `mkimg.qr.sh`: Описує профайл ISO образу (параметри ядра, роздільну здатність екрану, базові пакети).
   - `genapkovl-qr.sh`: Скрипт-оверлей, який "вживлює" наш скрипт `hardware_qr.sh` всередину ОС під час збірки, а також налаштовує автологін в консоль (tty1).
3. **`build_iso.sh`**: Меню вибору збірки (**Alpine** або **Arch**) у Docker:
   - `./build_iso.sh` — інтерактивне меню
   - `./build_iso.sh alpine` / `./build_iso.sh arch` — без меню
   - `BUILD_TARGET=arch ./build_iso.sh` — через змінну середовища
   - `build_iso_alpine.sh` / `build_iso_arch.sh` — окремі скрипти
4. **`arch-config/`**: Профіль **archiso** для Arch Live (`arch-hardware-qr.iso`).
5. **Скрипти тестування та розгортання**:
   - `run_qemu.sh`: Дозволяє миттєво протестувати згенерований образ у віртуальній машині QEMU без перезавантаження комп'ютера розробника.
   - `install_deps.sh`: Універсальний скрипт для встановлення всіх необхідних інструментів (Docker, QEMU) на нові комп'ютери під управлінням Arch, Debian/Ubuntu або Fedora.

## 🚀 Як зібрати образ самостійно
Якщо ви клонували цей репозиторій на новий ПК:
1. Запустіть скрипт встановлення залежностей: `sudo ./install_deps.sh` (встановить Docker, QEMU тощо).
2. Переконайтеся, що ви вийшли/зайшли в систему (щоб запрацював доступ до Docker).
3. Запустіть меню збірки: `./build_iso.sh` і оберіть **Alpine** або **Arch**.
4. Готовий образ:
   - Alpine: `alpine-hardware-qr.iso`
   - Arch: `arch-hardware-qr.iso`
5. Для перевірки: `./run_qemu.sh` (або `./run_qemu.sh arch`).

### Швидкість старту ISO

Скрипт збірки за замовчуванням замінює стиснення Alpine `modloop` з повільнішого `xz` на `zstd` рівень 1. Це збільшує ISO, але має зменшити час розпакування kernel modules під час старту.

Для A/B тесту можна зібрати варіанти:

```bash
MODLOOP_COMPRESSOR=zstd MODLOOP_ZSTD_LEVEL=1 ./build_iso.sh alpine
MODLOOP_COMPRESSOR=gzip ./build_iso.sh alpine
MODLOOP_COMPRESSOR=xz ./build_iso.sh alpine
```

Підтримувані значення `MODLOOP_COMPRESSOR`: `zstd`, `gzip`, `lzo`, `xz`.

## 🖥 Окремі скрипти без Live ISO

Якщо потрібно зібрати QR прямо з уже запущеної ОС, використовуйте окремі скрипти з папки `scripts/`.

### Windows

PowerShell-скрипт не потребує зовнішніх модулів: він збирає дані через CIM/WMI, генерує сумісний payload `V/1|...` і створює BMP з QR-кодом.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows_hardware_qr.ps1
```

Опційно:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows_hardware_qr.ps1 -Ticket 12345 -OutputPath .\hardware-qr.bmp
```

Результати: `hardware-qr.bmp` і `hardware-qr.payload.txt`.

### Linux

Linux-скрипт використовує стандартні системні джерела (`/sys`, `lscpu`, `lsblk`, `dmidecode`, `smartctl`) і `qrencode` для QR-коду. Для повніших SMBIOS/SMART-даних краще запускати через `sudo`.

```bash
chmod +x scripts/linux_hardware_qr.sh
sudo ./scripts/linux_hardware_qr.sh
```

Опційно:

```bash
./scripts/linux_hardware_qr.sh --ticket 12345 --png hardware-qr.png --payload hardware-qr-payload.txt
```

Результати: `hardware-qr.png` і `hardware-qr-payload.txt`.

## 🌟 Головні переваги
- **Швидкість**: Образ важить трохи більше 200 МБ і завантажується майже миттєво.
- **Універсальність**: Працює на будь-якому ПК з x86_64 архітектурою (Intel/AMD) та сумісний з Ventoy (рекомендовано).
- **Безпека**: Жодні дані не записуються на диски клієнтського ПК, система працює виключно в оперативній пам'яті.
- **Масштабованість**: Якщо потрібно додати нове поле (наприклад, MAC-адресу), достатньо просто змінити `hardware_qr.sh` і перезібрати образ одним кліком через `build_iso.sh`.
